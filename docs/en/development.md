## Examples and secrets

The four projects in [`examples/`](../../examples/README.md) are generated by `python scripts/build_examples.py` (never edit their
`pipelines/main.json` by hand) and tested with `python scripts/e2e_examples.py` (a scripted fake LLM; no keys, no cost).
Project memory has its own two-run test: `python scripts/e2e_memory.py`.
To compare API consumption with memory on/off, use
`python scripts/memory_report.py <project-root>` (reads `memory_usage` from the database).

**Nothing secret may reach Git.** `scripts/check-secrets.mjs` (`npm run check:secrets`) flags API-key formats, literal values in
`api_key`/`token`/`password` fields, user paths, personal e-mails, credential files and generated artifacts under `examples/`.
Run `npm run hooks:install` once per clone to make it a **pre-commit hook**; `npm test` also fails on any finding in `examples/`.
Secrets live only in user environment variables; project files hold at most a variable *name* or a `${NAME}` reference.

## Compilation, Hardening, and C++20 Security

The `CppCore/dev.py` script automates the full local development and build loop (TypeScript + Vite + CMake + MSVC/GCC). The native C++20 compilation incorporates open-source security best practices, vulnerability mitigation, and code analysis:

### Dev Orchestrator Options (`dev.py`)

| Command | Description |
| :--- | :--- |
| `python CppCore/dev.py` | Builds frontend, builds native C++20 backend with hardening, and opens the Studio. |
| `python CppCore/dev.py --no-run` | Only compiles (frontend and backend) without launching the GUI. |
| `python CppCore/dev.py --no-frontend` | Skips TypeScript/Vite compilation (useful during backend-only iterations). |
| `python CppCore/dev.py --test` | Compiles frontend + all native targets (including `arestrix-gateway`) and runs the **C++** suite via `ctest`. It does not run Vitest; use `npm test` for the frontend. |
| `python CppCore/dev.py --test-all` | Build + CTest + Vitest. |
| `python CppCore/dev.py --check` | Version, local assets, secrets and third-party licenses; no build. |
| `python CppCore/dev.py --gateway-smoke` | HTTP smoke test of `arestrix-gateway` with a fake upstream and budget rejection. |
| `python CppCore/dev.py --e2e` | Tutorial/examples end-to-end scripts. |
| `python CppCore/dev.py --full` | Build + CTest + Vitest + checks + gateway smoke; does not open the Studio and does not include `--e2e`. |
| `python CppCore/dev.py --asan` | Instruments binaries with **AddressSanitizer** for runtime detection of buffer overflows, *use-after-free*, and memory leaks. |
| `python CppCore/dev.py --clang-tidy` | Runs static analysis via **Clang-Tidy** using enterprise rules in `.clang-tidy` (C++ Core Guidelines and CERT C++). |
| `python CppCore/dev.py --cppcheck` | Runs behavioral static analysis via **Cppcheck**. |
| `python CppCore/dev.py --no-hardening` | Disables strict memory mitigation flags (useful for specific profiling scenarios). |

### Active Protection Layers in CMake

The `arestrix_security_flags` interface library in [`CMakeLists.txt`](../../CMakeLists.txt) injects native protections into compiler and linker invocations:

- **On Windows (MSVC):**
  - **Stack Canaries (`/GS`):** Detects buffer overflows on the stack before returning from functions.
  - **Control Flow Guard (`/guard:cf`):** Validates indirect call targets in both compiler and linker against ROP exploit vectors.
  - **Security Development Lifecycle (`/sdl`):** Enforces additional Microsoft runtime and buffer security checks.
  - **Address Space Randomization (`/DYNAMICBASE` & `/HIGHENTROPYVA`):** Enables 64-bit high-entropy ASLR.
  - **Data Execution Prevention (`/NXCOMPAT`):** Prevents executing code from memory segments designated as data (stack/heap).
  - **Code Quality and Third-Party Isolation:** Builds Arestrix code under `/W4`, while isolating external C libraries (`sqlite3.c`, `simdjson.cpp`, `webui.c`) with `/w` to eliminate false positives.
- **On Linux (GCC/Clang):**
  - **Hardened Stack Protection:** `-fstack-protector-strong`.
  - **Buffer Fortification:** `-D_FORTIFY_SOURCE=2`.
  - **Full RELRO:** `-Wl,-z,relro,-z,now` (marks dynamic symbol tables as read-only).
  - **Non-Executable Stack:** `-Wl,-z,noexecstack`.
  - **Format Security:** `-Wformat=2 -Wformat-security`.

## Tests and verification gate

`dev.py` builds the frontend and every native target (Studio, CLI, gateway and tests). The canonical local gate is:

```bash
python CppCore/dev.py --full   # build + CTest + Vitest + checks + gateway smoke
python CppCore/dev.py --e2e    # optional: tutorial/examples end to end
```

If you prefer individual steps:

```bash
npm test                                # frontend: Vitest
python CppCore/dev.py --no-run --test   # frontend build + all native targets + CTest
npm run check:version                   # version.txt, package.json, package-lock.json, CHANGELOG
npm run check:local-assets              # GGUF catalog + llama.cpp manifest
npm run check:secrets                   # secrets and personal data
python scripts/check_third_party_licenses.py
node scripts/gateway-smoke.mjs          # gateway proxy/budget smoke
```

The frontend suite covers graph validation and cycles, undo/redo, subflows, templates, settings
inheritance, telemetry, the resume engine, memory, MCP, projects and workspaces, the Office interface, SVG
vertices and i18n parity. The C++ suite includes the gateway budget store and local runtime catalog tests;
the gateway HTTP proxy should also be smoke-tested with a fake upstream when its routes change.

## Local runtime and AI Gateway

The local model runtime lives in `CppCore/src/local/` and writes to
`%LOCALAPPDATA%\Arestrix` (Windows) or `~/.local/share/arestrix` (Linux); `ARESTRIX_DATA_DIR` overrides
the root for tests. The catalog and pinned llama.cpp manifest are embedded from
`CppCore/runtime/*.json` and validated by `npm run check:local-assets`.

The on-prem AI Gateway is a separate executable, `arestrix-gateway`, built by the same CMake project.
Operator setup, budgets, keys and deployment are documented in
[`CppCore/gateway/README.md`](../../CppCore/gateway/README.md). For development, copy
`CppCore/gateway/arestrix-gateway.example.json` and run:

```bash
arestrix-gateway init --db arestrix-gateway.db
arestrix-gateway key create --name dev --budget-usd 10 --period monthly --db arestrix-gateway.db
arestrix-gateway serve --config arestrix-gateway.json
```

The Studio/runners use `ARESTRIX_AI_GATEWAY_URL`, `ARESTRIX_AI_GATEWAY_KEY` and
`ARESTRIX_REQUIRE_AI_GATEWAY`. Local providers are exempt; hosted providers fail closed when required and
the gateway is missing. See the [roadmap](roadmap.md) for the gateway/HA and Linux/CI gaps.

## Adding a language

Arestrix ships `pt-BR` and `en-US`. A new language needs five edits (example: `es-ES`):

1. **Dictionary.** `cp src/i18n/locales/en-US.json src/i18n/locales/es-ES.json` and translate the values;
   keep every key.
2. **Type.** In `src/i18n/types.ts`, add the code to `SupportedLocale` and an entry to `SUPPORTED_LOCALES`.
3. **Catalog.** In `src/i18n/index.ts`, import the JSON, add it to `resources`, and allow the code in the
   `setLocale` check.
4. **Selector.** Add an `<option>` to `#backstage-language-select` in `src/ui/ribbon/BackstageView.ts`.
5. **Verify.** `npm test` fails if any key is missing or extra between catalogs. Then `npm run build`
   (it also copies `dist/` to `CppCore/dist/`).

Every user-visible string goes through `t('key', 'fallback')`, never hard-coded.

## Third-party code policy

All external code is in `third_party/` and must be compatible with Taskflow's **MIT** license.
Pins, roles and the update process are documented in [`third_party/README.md`](../../third_party/README.md).
permissive licenses only (MIT, BSD, ISC, Apache-2.0) and public domain (SQLite, SPDX `blessing`). The single documented exception is the
Inter font (SIL OFL 1.1), which allows embedding. JavaScript dependencies are declared in `package.json` and checked
against the same list.

```bash
python scripts/check_third_party_licenses.py
```

Submodules:

```bash
npm run submodule:check    # report new upstream commits
npm run submodule:update   # move to the latest upstream
```

## Conventions that matter

- **No text shadows or glows** on any text, in any theme. Contrast comes from color and weight.
- **Ignore rules anchored with `/`** (`/build/`, `/runtime/`): an unanchored `build/` once hid
  `CppCore/src/build/` from the repository.
- Edits to the graph go through `ICommand` implementations so they stay undoable.
- JSON in the C++ backend goes through `Json` (simdjson), not another parser.
