# Support

Thanks for using Arestrix. Please use the channel that matches your request so the maintainers can
help efficiently.

## Documentation first

- [Documentation](README.md#complete-documentation) — guides for installation, architecture,
  graphs, agents, workspaces, MCP and development.
- [Examples](examples/README.md) — runnable projects and the scripted end-to-end tests.
- [Changelog](CHANGELOG.md) — user-visible changes and known limitations.
- [Dependency advisories](SEGURANCA_DEPENDENCIAS.md) — known npm advisories and mitigation status.

## Questions and ideas

Use [GitHub Discussions](https://github.com/frankalcantara/Arestrix/discussions) for:

- "How do I...?" questions.
- Setup and environment troubleshooting.
- Ideas that are not yet a concrete feature request.
- Showing projects built with Arestrix.

## Bugs and feature requests

Open an [issue](https://github.com/frankalcantara/Arestrix/issues/new/choose) and choose the
appropriate template. Include the Arestrix version (`version.txt` or release tag), operating
system, steps to reproduce and relevant logs.

Before opening an issue:

1. Confirm you are on the latest release or `main`.
2. Search existing issues and Discussions.
3. Remove API keys, tokens and personal paths from logs and screenshots.

## Security

Do **not** open a public issue for security vulnerabilities. Follow [SECURITY.md](SECURITY.md)
and use GitHub private vulnerability reporting.

## Scope and response times

Arestrix is a community project maintained on a best-effort basis. There is no guaranteed
response time, commercial support contract or bug bounty. Maintainers prioritise:

1. Security issues.
2. Regressions in supported releases.
3. Documentation and onboarding problems.
4. Feature requests aligned with the beta roadmap.

## Commercial and enterprise use

Arestrix is MIT licensed and may be used commercially. For enterprise deployment questions,
open a Discussion describing your environment and constraints; do not include confidential
information.
